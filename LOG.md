| 2026-10-28 | `da479cca` | Correct the BSRAM inference claim; RV32I is 40 instructions, not 37 | `LEARNING.md`, `SPEC.md` | Two factual errors found while reviewing the route against a pipeline endpoint. **(1) BSRAM.** `LEARNING.md` claimed `assign dout = mem[addr]` is placed in BSRAM, which was the stated reason a single-cycle core needs no hand-written memory. Measured on this board: BSRAM inference requires the read address to come from a **register**. A registered address infers BSRAM at 1024 words (10 LUT4, 272 MHz); an ALU-computed address at the same depth **fails place and route** (`Unable to find legal placement for cell mem.0.1 of type RAM16SDP4`). At 512 words it becomes 1211 LUT4 (14% of the chip, 138 MHz); at 256 words, 524 LUT4 (6%, 138 MHz). A single-cycle core computes its load address in the same cycle it needs the data, so its **data** memory is exactly the failing case, while its instruction memory is fine because the PC is a register. The FIFO demotion itself survives (a `reg` array is still enough), but it is a **LUT** array at affordable sizes, and the load path is now a phase C decision to make deliberately: small memory, or a registered read costing a stall. **(2) Instruction count.** The spec says "RV32I contains 40 unique instructions"; 37 silently drops `FENCE`, `ECALL`, `EBREAK`. Phase C now targets 40 encodings and 38 implemented behaviours (FENCE as NOP, ECALL/EBREAK trap to a UART halt). Also reopened SPEC open question 3 with a narrowed scope: the no-cross-compiler decision holds for phase C but will not hold for phase D's dependency-heavy test programs.
